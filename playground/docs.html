Blocklight documentation

A TypeScript library for styled city maps, 3D buildings, and JSON datasets. Start with the two runnable building blocks in the playground. The package is a local preview and has not been published to npm.

Set up a map

From the repository, run npm install and npm run dev. For another local project, build the package and install its directory. Import MapLibre’s stylesheet, give the container a height, and configure its worker in Vite:

import 'maplibre-gl/dist/maplibre-gl.css';
import { setWorkerUrl } from 'maplibre-gl';
import workerUrl from 'maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url';
import { createCityMap, buildings } from 'blocklight';
import { nyc } from 'blocklight/nyc';
setWorkerUrl(workerUrl);

const city = createCityMap({
  container: 'map', city: nyc, theme: 'blueprint',
  zoom: 14.8, pitch: 57, bearing: -28,
});
city.addLayer(buildings({
  id: 'buildings', source: '/data/buildings.geojson',
  promoteId: 'source_id', heightProperty: 'height_m',
}));

The core accepts your own city configuration and GeoJSON. NYC is an optional preset. Use buildings, points, lines, and polygons to compose layers. Themes are blueprint and paper.

Point at a JSON dataset

addBuildingDataset fetches data, joins it to geometry, and refreshes tiled geometry as the camera moves. source accepts a GeoJSON FeatureCollection URL or a Blocklight tile manifest. A top-level JSON array needs no records path.

import { addBuildingDataset, steppedScale } from 'blocklight';
const layer = await addBuildingDataset(city, {
  id: 'requests', source: '/data/city-buildings.json',
  data: {
    url: '/data/311-citywide.json', records: 'buildings',
    join: { feature: 'source_id', record: 'buildingId' },
    aggregate: { op: 'sum', field: 'count' },
  },
  color: steppedScale('value', [
    { value: 0, color: '#26354d' },
    { value: 1, color: '#e8c98a' },
    { value: 20, color: '#bc6447' },
  ]),
});

Use a unique layer ID if you have already added a building layer. The join compares string or numeric keys after trimming whitespace. It does not pad IDs or perform spatial matching. Duplicate geometry keys remain unassigned rather than multiplying a record.

Multiple datasets and color schemes

Pass a datasets array to addBuildingDatasets. Each entry has an id, label, data configuration and color scale. Entries can use different URLs or different fields in one file. JSON fetched from the same URL is cached by the controller.

const layer = await addBuildingDatasets(city, {
  source: '/data/city-buildings.json',
  datasets: [housing, heating, plumbing], // DatasetDefinition objects
  active: 'housing',
});
select.replaceChildren(...[housing, heating, plumbing].map(dataset => {
  const option = new Option(dataset.label, dataset.id);
  return option;
}));
select.onchange = async () => {
  try {
    await layer.setDataset(select.value);
    // Refresh your own detail panel using layer.getValue(selectedFeature).
  } catch (error) { status.textContent = error.message; }
};

See complete dataset definitions in the complex example. Switching keeps the camera and selected feature state. Use layer.active for the active ID, getValue(feature) for the aggregate, getRecords(feature) for matching JSON records, and dispose() to remove the layer and its listeners.

Aggregation and raw records

Aggregation defaults to one count per matching record. Use { op: 'sum', field: 'count' } for preaggregated records. Sum fields support dot paths such as categories.PLUMBING. Add missing: 0 when absent categories mean zero; otherwise missing or nonnumeric amounts are errors. property changes the output property from value; your color scale must reference the same name.

// Raw records with a building identifier:
data: {
  url: '/data/requests.json',
  join: { feature: 'bin', record: 'building_bin', multiplicity: 'bin_count' },
  aggregate: { op: 'count' },
}

For tiled geometry, joins on keys other than the stable feature ID require a citywide multiplicity property. Supply its count on each feature: only count 1 is eligible. The generated NYC geometry provides base_bbl_count and mappluto_bbl_count for tax-lot joins. The example bin_count above must be supplied by your own geometry pipeline. A tax lot can contain multiple buildings; raw BBL joins deliberately leave these ambiguous requests unassigned.

Click details and view changes

city.on('select', selection => {
  details.textContent = selection
    ? `${layer.getValue(selection.feature)} requests`
    : 'Select a building';
});
city.map.easeTo({ pitch: 57, bearing: -28 });
city.setTheme('paper');
city.setVisible('requests', false);
// When the page/component is removed:
city.destroy();

Render data as text or escape it before inserting HTML. The select event provides layerId, feature, and lngLat; clearing emits null. For custom data updates, setData(id, geometry, { preserveSelection: true }) requires a stable promoteId. Refresh your detail UI after switching datasets because the selection itself has not changed.

Citywide NYC data

Run npm run data:city to download public footprints, streets, and 2025 HPD housing requests across all five boroughs. This is a substantial initial download. Generated assets are ignored by Git; a smaller bundled sample works immediately. The demo opens over Midtown in 3D and loads building tiles as you explore.

The prejoined JSON includes provenance, period, matched and unmatched totals, and per-building category and status counts. Single-building lots match by BBL; multiple-building lots require an unambiguous point inside a footprint. Requests are reports, not confirmed violations. Category views show linked category counts; unmatched totals and status/matching details remain explicitly labeled as all housing requests.

Dots at city scale

The demo switches to building dots below zoom 14, then returns to footprints or 3D buildings as you zoom in. Dataset colors and selected details persist. The citywide overview includes every building with linked housing requests plus one in 32 other footprint IDs. Each dot is one building, not a cluster; the overview is labeled as a sample.

For your own map, use buildingPoints(geojson) to preserve footprint IDs and attributes on point features. Add a points layer with maxzoom: 14, and buildings with minzoom: 14. The marker is the footprint bounding-box center, not an entrance or a guaranteed interior point. Use a small prebuilt point source for large cities, so zooming out does not download every polygon.

React and lifecycle

Use the optional blocklight/react entry point; the React example demonstrates Strict Mode mounting and cleanup. The framework-independent core exposes the underlying MapLibre map as city.map. Await city.ready for style setup; it does not mean all data has finished rendering. Subscribe to error to show loading failures.
