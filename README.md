# Blocklight

**Beautiful cities. Your data.**

A TypeScript city-mapping toolkit built on MapLibre GL JS. Quiet cartography,
3D building footprints, composable data layers, and a shared language for maps
and legends. Inspired by the Blueprint and Paper maps in Henry Williams's Prospect.

## Run the playground

Requires Node 22.12+ and a browser with WebGL 2.

```sh
npm install
npm run dev
```

Open the local URL printed by Vite. The demo opens in **3D over Midtown**. The default example maps **2025 NYC 311
housing requests handled by HPD**, linked to individual building footprints.
Building colors encode request counts in both 2D and 3D. Click a building for its
address, height, request categories, status counts, and matching explanation.

Use **3D buildings** or **2D plan** to change perspective. The selected building,
its highlight, and its detail panel persist across both views. Blueprint/Paper
themes and layer visibility work in either perspective. Use the Dataset selector to switch between housing, heating/hot water, and plumbing, each with its own color scheme. The React example is at
`/react.html`; documentation is at `/docs.html`.

Use **Download JSON** to export the sample or **Load JSON** to load another dataset
using the same schema and footprint IDs. See [the JSON contract](#building-data-json).

All demo data is served locally. No API key, paid tile service, database,
Prospect server, or external runtime data request is needed.

**Status:** local v0.1 preview. Not published to npm or GitHub. Package-name
availability has not been checked. The MIT license applies to code; source data
has separate terms in [DATA.md](DATA.md).

## Use the library

The npm workspace package lives in `packages/blocklight`. Build a portable tarball:

```sh
npm run build -w blocklight
npm pack -w blocklight
# In another project:
npm install /path/to/blocklight-0.1.0.tgz maplibre-gl
```

```ts
import 'maplibre-gl/dist/maplibre-gl.css';
import { createCityMap, buildings, polygons, points, steppedScale } from 'blocklight';
import { nyc } from 'blocklight/nyc';

const city = createCityMap({
  container: 'map', // Give this element an explicit height in CSS.
  city: nyc,
  theme: 'blueprint',
});

city.addLayer(polygons({
  id: 'land', source: '/data/land.geojson', interactive: false,
}));
city.addLayer(buildings({
  id: 'buildings', source: '/data/buildings.geojson', heightProperty: 'height_m',
}));

city.on('select', selection => console.log(selection?.feature.properties));
city.on('error', error => console.error(error));
await city.ready;
city.setTheme('paper'); // Repaints in place; preserves sources and camera.
// city.destroy() when the map leaves the page.
```

`nyc` supplies geographic defaults only. Data URLs always belong to the caller.
For another city, supply `{ id, name, center, zoom, bounds }` or pass a center
and zoom directly. No NYC assumptions exist in the rendering core.

## API

- `createCityMap(options)` → controller with the underlying MapLibre `map`.
- `buildings`, `points`, `lines`, `polygons` → layer definitions accepting GeoJSON
  objects or URLs, attribution, visibility, zoom bounds and interactivity.
- `addLayer`, `removeLayer`, `setVisible`, `setData`, `setColor`, `setTheme`,
  `selectFeature`, `clearSelection`, `destroy`.
- `on('select' | 'hover' | 'error', handler)` → unsubscribe function.
- `ready` → promise resolving when the base map and layer definitions are installed.
  Remote GeoJSON may still be loading; use MapLibre's `idle` event for rendered data.
- `steppedScale(property, stops, noDataColor)` → expression and matching legend.
- `toMapLibreLayer`, `sourceId`, `baseStyle`, `themes` → low-level integration
  with an existing MapLibre map. Add a GeoJSON source with the returned source ID
  before adding the generated layer. Use stable feature IDs for interactions.

Layers are drawn in insertion order. Put land and streets first. Heights and
base heights are meters; geographic coordinates are WGS84 `[longitude, latitude]`.
Use `buildings({ ..., extruded: false })` for flat footprint context.
Missing/invalid heights render at ground level. Null values in a color scale
use its explicit no-data color. The first scale color extends below its first
listed value. Thresholds must be strictly increasing.

GeoJSON `Feature.id` is preserved; missing IDs are generated by MapLibre.
Selection is cleared on data replacement, layer hiding, or removal. Use
`selectFeature(layerId, feature, lngLat)` to transfer a known feature with a stable
ID to another visible representation. The playground does this across 2D/3D. The core
never interprets a feature as a property record, resident, or score.

## React

React is an optional peer dependency, isolated behind the `/react` entry point.

```tsx
import { useMemo } from 'react';
import { CityMapView } from 'blocklight/react';
import { buildings } from 'blocklight';
import { nyc } from 'blocklight/nyc';
import 'maplibre-gl/dist/maplibre-gl.css';

export function Map() {
  const layers = useMemo(() => [
    buildings({ id: 'buildings', source: '/data/buildings.geojson' }),
  ], []);
  return <CityMapView city={nyc} layers={layers} theme="blueprint"
    style={{ height: 600 }} onError={console.error} />;
}
```

Theme, layers, and callbacks update live. City, camera, and engine options are
initial values; use the controller from `onReady` for later camera changes, or
change the component's React key. Memoize the layers array: replacing it
reinstalls layers and clears selection. SSR can import the package; map creation
happens only after browser mount. React Strict Mode is exercised by the example.

## Scope

This first release supports GeoJSON layers and footprint extrusions. It does
not yet include vector-tile adapters, packed-geometry codecs, architectural
meshes, a citywide data service, or interactive time filters for requests.
A fresh checkout includes a small Midtown-area sample. `npm run data:city`
generates all-five-borough coverage and enables viewport loading automatically.
Below zoom 14, the demo switches to a compact building-dot overview. It includes every building with linked housing requests plus one in 32 other footprint IDs, labeled as a sample. Zooming back in restores building shapes and preserves the selection. A second-city example and real downstream adoption should
precede a stable API release.

## MapLibre 6 worker setup

Bundlers must resolve MapLibre's separate module worker. For Vite, configure it
once before creating maps (see `playground/src/worker.ts`):

```ts
import { setWorkerUrl } from 'maplibre-gl';
import workerUrl from 'maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url';
setWorkerUrl(workerUrl);
```

For other bundlers, serve `maplibre-gl-worker.mjs` and its sibling
`maplibre-gl-shared.mjs` from MapLibre's `dist` directory at a public path,
and call `setWorkerUrl` with that worker URL. Keep the files matched to the
installed MapLibre version. Blocklight does not overwrite global worker settings.

## Building data JSON

The playground fetches `playground/public/data/311-buildings.json` separately from
`buildings.geojson`. The JSON is an aggregated attribute table, not a second copy
of the geometry. Each `buildings[]` record joins `buildingId` to a footprint's
`properties.source_id` and provides `count`, `categories`, `statuses`, `addresses`,
`latestCreatedAt`, and `matchMethods`. Top-level `schemaVersion`, `title`, `agency`,
`period`, `source`, `join`, and `summary` describe the extract and its matching.

Download the actual file as a valid template. The upload control checks the schema,
unique IDs, geometry compatibility (individual IDs for the small sample, the
geometry-version marker for citywide files), and whether category,
status, matching-method and summary counts reconcile. Invalid uploads leave the
existing map intact. Files are processed locally in the browser and never uploaded
to a server. The demo limit is 50 MB. Use `npm run data:nyc` then `npm run data:311`
to rebuild a matched pair after changing footprint coverage.

A missing building record means **no requests linked in this extract**, not proof
of no requests. The default filter is HPD housing requests created in 2025, not
all 311 agencies. Status is the value at the snapshot's fetch time.

## Render information on click

The core emits a selected feature and layer ID; the application owns the panel.
For example, join a JSON record to the selected building and render it safely:

```ts
const records = new Map(data.buildings.map(record => [record.buildingId, record]));
city.on('select', selection => {
  const record = selection
    ? records.get(String(selection.feature.properties.source_id))
    : undefined;
  document.querySelector('#details').textContent = record
    ? `${record.count} linked requests`
    : 'No linked requests in this sample';
});
// A close button can call city.clearSelection().
```

The playground expands this into an accessible labeled panel, a close button,
Escape-key dismissal, category counts, metadata and source attribution.

## Citywide static data

Run `npm run data:city` for the full city. Downloads are cached in `.cache/` and
can resume after interruption. The pipeline downloads official footprints and
streets, fetches 2025 HPD requests in monthly aggregates, verifies source totals,
joins requests conservatively, and writes:

- `city-buildings.json` / `city-streets.json`: geometry manifests.
- `city/buildings/{x}/{y}.geojson` and `city/streets/{x}/{y}.geojson`: fixed zoom-14
  geographic files, with complete features duplicated across intersected cells.
- `311-citywide.json`: the citywide attribute table, separate from geometry.
- `city.json`: completion marker published last; enables citywide mode.

`GeoJSONTileLoader` loads only intersecting cells, deduplicates feature IDs,
caches at most 64 tiles, accepts an AbortSignal, and bounds overview requests.
The demo discards obsolete loads after camera changes and carries the selected
building's record and highlight through 2D/3D changes and viewport refreshes.
It retains Midtown as the opening camera. All runtime requests stay on the
same static host; no database or live NYC API is required.

The large generated city assets are gitignored. Host them alongside the demo
or distribute them as a separate data release; they are not included in the
npm package. A clean checkout uses the bundled small sample until the citywide
build is complete. Source snapshots can change: if a cached build fails source
count verification, move the relevant `.cache/citywide-*` directory aside and
re-fetch a consistent snapshot.

The two code examples below the playground show a simple GeoJSON building map
first and a more complete citywide 311 configuration second.

## Configurable datasets

`addBuildingDataset(city, options)` accepts a geometry `source`, a `data` object
(`url`, optional `records` dot path, `join`, `aggregate`, optional output `property`),
and a `color` scale. Aggregation defaults to counting records; use
`{ op: 'sum', field: 'categories.PLUMBING', missing: 0 }` for nested numeric totals.

`addBuildingDatasets(city, { source, datasets, active })` accepts named definitions
with `{ id, label, data, color }`. Call `await layer.setDataset(id)` to switch;
`layer.active`, `layer.getValue(feature)` and `layer.getRecords(feature)` support
custom controls and details. Switching preserves camera and feature selection,
and shared URLs are fetched once. Call `dispose()` to remove the layer.
Refresh your own details after switching because the selection has not changed.

For tiled joins on a key other than the stable feature ID, supply
`join.multiplicity`: a feature property containing the citywide number of
footprints sharing that key. Only a count of one is eligible. Generated NYC
geometry includes `base_bbl_count` and `mappluto_bbl_count`. This prevents
lot-level records from being duplicated over multiple buildings.

See `playground/src/datasets.ts` for the demo's three configurations and
`/docs.html` for complete setup, join and switching examples. For custom data
replacement use `setData(id, geometry, { preserveSelection: true })` with a
stable `promoteId`.

`buildingPoints(geojson)` converts footprints to bounding-box-center point markers while retaining IDs and properties. Combine points with `maxzoom` and buildings with `minzoom` for your own zoom-dependent representations. `npm run data:overview` rebuilds the citywide dot file from existing city assets.
